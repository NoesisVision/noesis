NoesisStore

One typed door to .noesis/graph/. Spec: docs/work/improvements/noesis-store.md, decision 76 in docs/decisions.md, 2026-09-13.

1. Where the store sits

Two entry points, one service layer. Writes go through repositories and the store to files; reads never touch files. The watcher and indexer rebuild the in-memory graph from the files, including changes git made underneath.

2. Disk layout under .noesis/

graph/ holds knowledge graph files and nothing else, one directory per object at every depth, named by the key. sources/, tmp/ and logs/ are ignored by git through the .gitignore the service writes.

3. Containment model and handles

A collection is a directory, one Zod schema and named child collections. A handle is created without touching the filesystem; child handles are scoped to one parent key and require the ancestors to exist on every I/O.

4. Write, delete, concurrency

set validates, serialises the parsed value, writes a temporary file in the object's directory and renames it over data.json. There is no coordinator and no lock: the last complete rename wins, in one process or two.

5. Key decisions (decision 76, amends 68 and 74)

1Layout: <key>/data.json

One shape at every depth under .noesis/graph/. Replaces flat <slug>-<id-suffix>.json and change.json. Diffs show an id, not a slug.

2Key is the repository's choice

Slug for changes, contract id elsewhere. The store neither reads the key from the data nor checks that they agree.

3Last write wins, no locks

Atomic rename is the whole guarantee. No coordinator, no per-object queue. Real concurrency is two processes and git, which no in-process lock reaches.

4No data.json, no object

Such a directory is garbage: skipped by keys(), removed recursively by a sweep at boot before the indexer runs. Decision 74's fallback goes.

5Services read the graph only

Repositories are the write path. The indexer walks keys() and get(). No getAll, no sorted listing, no metadata in a read.

6updated_at dropped

It was file mtime, which git checkout rewrites, and nothing in the UI reads it. Returns as data a repository writes when a view needs it.

7FileRef.hash dropped

FileRef.check() had no caller. source_sha becomes the import service's concern; a source id is already a content hash.

8No has(key) for now

Existence is the graph's answer. Added only if a repository needs it without a parse.

9Name: NoesisStore

createNoesisStore, NoesisStoreError, NoesisStoreErrorCode.

10Two meanings of "source"

Information sources (Conversation, Document) are graph content under the change. Source files (transcripts, .md, .pdf) go to sources/, outside store and index.

11sources/ is git-ignored

Large, often private; the graph built from them is what gets committed. NoesisDir.ensure() adds it to the maintained .gitignore.

12What changes in code

FileRepository and StoredFile go; seven repositories become thin wrappers; watcher scoped to graph/; conventions.md rewritten; two test changes moved by hand.
