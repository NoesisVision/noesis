Collaborative design document workspace — Stage 1 prototypes

Superseded. These three concepts were the Stage 1 comparison; the direction chosen from them is the document view. They are kept here as reference and run against a frozen copy of the sample data.

Three low-fidelity concepts for the same specification, rendered from one shared sample document (an appointment-booking system with two bounded contexts, four application services, 19 use cases, six actors and a pending agent proposal). Only the navigation shell differs, so the comparison is about the interaction model rather than the content.

Current direction

Document view

The specification read as one document: goal and business context first, then use cases with their rules, inputs, outputs and scenarios. The left rail is the table of contents, and every block is bound to one typed schema element — no free-floating prose.

Shared conventions

Codebase delta +New ±Modified −Removed — Existing elements are unmarked. Markers carry a glyph and a word, never colour alone, and stay quieter than the element name and its behaviour-type badge. Modified is derived from baseline-comparable fields only.
Behaviour typecommand query event — a badge beside the name, never a document section.
RelationshipsHidden until something is selected, then only the connections that belong to that selection appear.
Sequence diagramsProjected from the scenario’s explicit ordered path through the behaviour graph — the same path, two lens projections.
ProposalsAccepted or rejected whole; the review lists added, changed, removed, specification-only changes and challenged human decisions.

Prototype limits

Edits, comments and proposal decisions live in memory only and reset on reload. Collaboration is represented (presence, comments, mentions) but not actually live. Layout targets 1280 px and wider. The lens choice is the only state that persists, and only where the browser allows storage.
