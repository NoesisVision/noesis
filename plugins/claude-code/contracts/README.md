# Contracts

This directory is a build output. In a checkout it holds only
this file; in the published plugin it holds the contracts every
knowledge graph file and import payload must satisfy, as JSON Schema the
model reads directly: `<contract>.schema.json`, and `<contract>.example.json`
beside the larger ones. It is the one readable copy of
the contracts anywhere; the service bundles the zod schemas they are generated
from into its executable and ships none.

## How it is made

The service owns the contracts and generates them; the plugin decides where
they land. `server/backend/tools/contracts.ts` lists the contracts by the
name they ship under, importing each zod schema from wherever it lives, so no
folder layout is assumed. `server/backend/tools/generate-contracts.ts`
(`bun run contracts <dir>` there) writes the JSON Schema of each with
everything it is built from inlined: a file points at nothing outside
itself. Only schemas ship. The domain objects that sit next to them at the
source stay behind, and a codec shows as the string it decodes, which is what
an agent writes. Each file names the service version it was generated by in
its `$comment`; plugin and service release in lockstep, so it is the plugin's
too.

`tools/build-contracts.ts` here empties this directory, keeping only this
README, so a contract the service dropped disappears, and then calls the
service's script. It runs as the plugin's `bun run build`
(`bun run build:plugin` from the repo root), as `prepack` so a packed tarball
always carries fresh files, and inside the plugin's tests, which assert that
nothing stale survives and that every contract a skill names exists. What
the files hold is asserted by the service's
`test/unit/contracts-json-schema.spec.ts`, which also refuses a refinement or
a transform in any zod source under `src/app/`: JSON Schema cannot state one
and would drop it silently.

## How it is read

Skills name a contract by a path under this directory, as
`${CLAUDE_PLUGIN_ROOT}/contracts/<contract>.schema.json`, and read it with the
model's own file tool at the step that produces the file. Contracts never
travel over MCP.

Do not edit anything here by hand: change the zod schema under
`server/backend/src/app/`, add it to `server/backend/tools/contracts.ts` when
it is a new contract, and rebuild.
