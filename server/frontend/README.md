# frontend

The Noesis web UI: a client-only React SPA on Vite and TanStack Router
(decisions 63 and 67). There is no SSR and no server-side execution of any
kind — anything that needs a server is a Hono route on the backend's `/ui`
surface, reached through the typed `hc<AppType>` client.

## Scripts

| Script                    | What it does                                           |
| ------------------------- | ------------------------------------------------------ |
| `bun run dev`             | Vite dev server on `:5173`, proxying `/ui` to `:3000`  |
| `bun run build`           | Production build to `dist/`                            |
| `bun run check-types`     | `tsc --noEmit`                                         |
| `bun run generate-routes` | Regenerate `src/routeTree.gen.ts` without a dev server |
| `bun run preview`         | Serve the built `dist/` locally                        |

Run both servers together from the repo root with `bun run dev:server`.

## Layout

```
index.html                  # Vite entry; mounts #app
src/
  main.tsx                  # creates the router + QueryClient, mounts the tree
  router.tsx                # createRouter over the generated route tree
  routes/                   # file-based routes; each file exports only `Route`
  components/               # route components and shared UI
  integrations/tanstack-query/
  styles.css                # Tailwind entry
```

Route files export `Route` and nothing else — biome's
`useComponentExportOnlyModules` rejects both extra exports and unexported
components there, and an extra export would defeat the route's code-splitting.
View components therefore live in `src/components/`.

`src/routeTree.gen.ts` is generated by `@tanstack/router-plugin` on dev and
build; it is committed, so regenerate it with `bun run generate-routes` if you
add routes without running either.

## Serving in production

`bun run build` emits `dist/`, which the Dockerfile copies to `/app/ui`; the
backend serves it from `UI_DIST_PATH` with an SPA fallback. One image, one
process.
